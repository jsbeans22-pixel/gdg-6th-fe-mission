# 상태 관리(State Management)는 무엇이고, 왜 필요할까?
검색어 / 장바구니에 담은 상품들 / 로그인한 사용자의 정보 등
이런 데이터들은 사용자의 행동에 따라 계속해서 바뀐다.
이렇게 변하는 데이터를 상태(state)라고 부른다.

그런데 프로젝트가 커지게 되면, 이를 관리하기 힘들어진다.
동일한 상태를 여러 페이지에서 사용하게 되면서
컴포넌트가 많아지고, 코드가 복잡해지게 된다.

이를 해결하기 위해 사용하는 개념이 상태 관리!

상태 관리를 하게 되면
- 데이터의 일관성 유지(데이터가 모든 화면에서 동일하게 보임)
- props 전달 감소
- 유지보수 쉬워짐(상태를 한곳에서 관리하므로)

이런 장점들이 있다.

# Context와 useContext는 무엇인가?
React에서 Context는 여러 컴포넌트가 데이터를 공유할 수 있도록 도와주는 기능이다.
보통 부모 컴포넌트에서 자식 컴포넌트로 props를 통해 데이터를 전달하지만, 컴포넌트 구조가 깊어질수록 계속 전달해야 하는 문제가 발생한다. 이를 props drilling이라고 한다.

이 문제를 해결하기 위해 React에서는 Context 기능을 제공한다.

Context와 useContext는 다음과 같이 구분된다.

Context
→ 데이터를 공유하기 위한 공간(공용 저장소 역할)
useContext
→ Context 안의 데이터를 가져오는 Hook

구조를 보면 다음과 같다.
const MyContext = createContext();
* createContext() > Context를 생성한다.

const value = useContext(MyContext);
* useContext() > Context 안의 데이터를 가져오는 Hook이다.

이렇게 하면 중간 컴포넌트를 거치지 않고, 필요한 컴포넌트가 직접 데이터를 사용할 수 있다.
즉, props를 여러 단계로 전달하지 않아도 되어 코드가 더 간단해지고 유지보수가 쉬워진다.

# Context가 있는데도 상태 관리 라이브러리를 사용하는 이유?
Context는 여러 컴포넌트가 데이터를 공유할 수 있게 해주는 기능이지만,
상태가 많아지고 복잡해질수록 몇 가지 한계가 발생한다.
1. 상태가 변경될 때 관련된 컴포넌트들이 함께 리렌더링될 수 있어 성능 문제가 생김
2. 여러 개의 Context를 사용하게 되면 코드 구조가 복잡해져 유지보수가 힘들다.

그래서 규모가 큰 프로젝트에서는 상태 관리 라이브러리를 사용헤 상태를 더더욱 체걔적으로 관리한다.

이 경우 불필요한 리렌더링을 줄이고, 데이터 흐름을 파악하기 쉽게 해준다.

# 라이브러리의 종류
1. Redux
상태를 하나의 저장소(Store)에서 관리해 데이터 흐름이 명확하다.

하지만 구조가 비교적 복잡하고 작성해야 하는 코드 양이 많아 초보자에게는 다소 어렵다.

2. Zustand
가벼운 상태 관리 라이브러리로,
hook 기반으로 동작하며 사용 방법이 간단하다.

useState와 비슷한 느낌으이라 React 입문자도 쉽게 사용할 수 있다.

3. Jotai

Jotai는 상태를 atom이라는 작은 단위로 관리하는 라이브러리이다.

상태를 잘게 나누어 관리할 수 있어 필요한 부분만 렌더링된다는 장점이 있다.

하지만 개념이 조금 낯설게 느껴질 수 있다..

나는 초보자가 쉽게 사용이 가능하다고 해서
Zustand를 사용하기로 했다.
